# Duplicate and purpose-overlap candidates

`find-duplicates --index <manifest> --mode bodies` returns bounded structural candidates with both symbol IDs, source ranges, file/context hashes, similarity reasons, differences and review caveats. Use `--symbol <id>` to narrow to one method, `--project <relative-project>` to filter, and normal `--limit`, `--offset`, `--snapshot` paging. This command checks freshness before returning saved analysis.

The current semantic detector normalizes bound parameter and local names while retaining literal values, member/type/project identities, conversions, operators, checked context and supported implicit argument values. It distinguishes a renamed local from a different called business operation. An exact or renamed structural match is still not proof of behavioral equivalence. The old lexical detector's backslash/identifier erasure and short-body false groups are not current semantic results.

Near candidates use bounded token shingles and ordered-token comparison with default minimum score 0.90. The detector reports important differing tokens and positions for review. Bodies shorter than 24 normalized tokens are excluded by default; constructors, accessors, generic methods, async/iterator bodies and other unsupported forms have explicit omissions. Inspect returned coverage, omitted-method counts and budget notices. An empty page does not establish absence of duplication across unsupported or omitted code.

Default limits cap 100,000 methods, 4,096 tokens per body, two million total tokens, 64 MiB catalog and 16 MiB scan, 500,000 pair visits, 100,000 comparisons and 10,000 findings. Posting/key/entry limits also bound candidate generation. Work caps and suppressed postings remain visible. The full token vocabulary stays in the saved catalog; ordinary duplicate query responses return compact evidence rather than the complete body store. Projects with multiple realized contexts sharing one physical project path are conservatively omitted from duplicate extraction, with explicit `ambiguous-project-context` reasons. Reindex an older generation to create the current semantic catalog.

`find-duplicates --index <manifest> --mode purpose --symbol <id>` instead ranks possible overlap using authored documentation and structural facts for a selected method. It does not depend on generated descriptions or a model. Similar purpose is not structural duplication or behavioral equivalence; names and descriptions can conceal different business rules.

The historical eConnector count of 711 groups came from the old lexical detector and includes known false matches. It is retained as diagnostic history, not evidence for the replacement. Current engine tests cover renamed variables, literal/member differences, implicit caller information, checked arithmetic, bounded work and candidate evidence. The labeled study and resource qualification must report their own corpus, thresholds, hashes, false positives and omissions before any broader quality claim. CodeAtlas never merges or deletes application source.

## Labeled public evidence — 21 October 2026

Before execution, thresholds were fixed for complete pair enumeration and zero false exact/renamed semantic-difference matches. The final copied-Core probes passed two small corpora: 66 known development pairs and 120 fresh source-authored pairs, each with two exact/renamed positives and zero false-positive/false-negative structural classifications. A fresh reviewer checked every label in the latter corpus before seeing detector output. Both scans were uncapped. The known corpus filtered eight short methods and therefore does not by itself exercise all eligible business-rule negatives; the fresh corpus does.

Domain-review near matches are reported separately and are not counted as successful useful duplicates. A purpose probe retrieves the intended renamed helper at rank one, but also retrieves a deliberately misleading same-documentation/different-rule method at rank one. Its lexical/no-equivalence caveats are present. This is an observed purpose precision limitation, not proof that the negative is a useful consolidation candidate.

[Public corpora, source-review record, harness and metrics](../tests/Qualification/Duplicates/README.md) support reproduction. [October qualification](QUALIFICATION-2026-10.md) records the 0.00.23 private eight-pair source/usefulness sample, three accepted resource pairs, ordinary-query comparison and complete coverage accounting. Synthetic pair accuracy does not establish application-wide duplicate recall or safe merging. Purpose ranking changes require their separate regression/evaluation evidence.
