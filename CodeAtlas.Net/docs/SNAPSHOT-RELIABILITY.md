# Snapshot reliability, freshness and recovery

Milestone 4 qualification uses the authorized local Windows 11 machine, .NET SDK 10.0.402 and its local filesystem. This is a process-interruption and filesystem-permission guarantee; network shares, power-loss durability, filesystem aliases and case-sensitive Windows directories are not qualified. Linux packaging/qualification remains milestone 8 work.

## Publication contract

Each normalized absolute solution path identifies its own `.codeatlas/solutions/<file>-<SHA256>/current.json`. Windows path comparison is ordinal case-insensitive and accepts either separator. Symbol identities retain their existing display-relative project paths. Two solutions in the same directory have separate writer locks, pointers and reports.

A writer acquires the exclusive `.write.lock`, creates a fresh `generations/<indexId>/` directory, and writes exactly `index.json`, `overview.md`, `warnings.txt`, and `timings.json`. Each artifact is hashed as it is written and flushed to disk. A final successful input check precedes one atomic pointer commit. Windows replaces an existing pointer with `File.Replace`; first publication uses `File.Move` without overwrite. The manifest records solution/index identity, artifact byte lengths and SHA-256 values. The index schema and the manifest version are independent compatibility boundaries.

A reader resolves the small pointer once with delete sharing, binds every report path to that generation, verifies the three report hashes, and verifies the full index hash during its single JSON deserialization. It validates schema, nested required data, unique type/method identities and manifest/index identity. It never resolves the pointer again during the command. This detects accidental corruption and mixed files; it does not authenticate hostile modification of both a manifest and its files.

A failed/cancelled pre-commit writer cannot activate its partial directory. After commit there is no cancellable ancillary report publication. Readers that already resolved the previous generation retain valid paths because old generations are retained. A failed first publication leaves no active snapshot and requires another index command. Concurrent publication returns `index_busy`; disk/permission failures return `snapshot_io_failed`. Failure to read/hash an input is a failed publication guard, even though status queries describe that check as `unknown` with diagnostics.

Old and incomplete generation directories remain on disk for diagnosis. There is no automatic pruning: deleting generations while readers hold paths requires a separate lifetime policy. Space usage therefore grows with rebuilds. Do not edit active artifacts. Rebuild after a corrupt/incompatible snapshot; there is no silent fallback. To inspect a retained older generation, its direct `index.json` is available only in legacy/unverified compatibility mode.

## Input model and coverage

The versioned input manifest hashes discovery-root source/configuration files, explicit loaded/linked/additional/analyzer-config documents, ancestor configuration candidates (including absent candidates), evaluated imported projects, actual `ProjectAssetsFile`/intermediate restore inputs, resolved external metadata/analyzer files, selected MSBuild/compiler binaries and host, and SDK/runtime directory inventory. It compares a digest of the process environment; raw environment values are never serialized. Only exact environment mutations observed while CodeAtlas registers MSBuildLocator are immediately restored, under the same capture lock, so they do not leak into child processes. Caller environment changes remain relevant and invalidate the snapshot.

Input discovery first opens a workspace without compiling projects or loading generators, evaluates physical build inputs and captures their content hashes. Only then does a second semantic workspace load and compile. Its discovered input set must match the captured set, and captured hashes/environment/inventories must still match after loading and analysis. A newly discovered or changed tracked input aborts indexing. A deterministic imported `DefineConstants` edit at the fingerprinting boundary proves that old semantics cannot be published against new import bytes; rebuilding then produces the new conditional symbol.

MSBuild inputs are evaluated with explicit design-time defaults after workspace loading. This replay cannot prove every custom workspace context and is reported as `evaluation_context_replayed`, not complete coverage. Arbitrary tasks and conditional/wildcard external imports may read undisclosed inputs; `dynamic_build_inputs_unverified` and `build_inputs_unverified` remain explicit. JSON includes compact coverage status, scope, issue count and distinct reason codes; per-project details are saved in the immutable warning report, separately counted from MSBuild warnings. Project coverage records selected target, declared targets and detected generators. Multi-target and source-generator coverage remains partial. Ordinary SDK-generated loaded files can still be explicit hashed inputs.

A changed tracked input produces `stale`. Equal tracked inputs with incomplete evidence produce `unknown` and concrete coverage issues. Complete evidence is required for `fresh`; `isStale: false` is not a completeness claim. Read/hash errors produce `unknown` plus diagnostics for queries, and reject publication. Legacy direct JSON retains queries/paging but reports unverified snapshot integrity and unknown input coverage; it does not gain the generation contract. Saved queries do not evaluate MSBuild or load Roslyn.

## Qualification evidence

Focused persistence and real Windows qualification pass: immutable old/new concurrent readers; an open pointer reader during replacement; same-solution writer exclusion; independent solutions; cancellation and injected write/flush/publication failures; missing/truncated/checksum-mismatched artifacts; malformed/incompatible/unsafe manifests; same-length tampering of all three report types; single-stream index tampering; and unchanged storage after reads.

Actual child processes are killed before pointer replacement and after publication. The pre-commit kill retains all previous artifacts; the post-commit kill exposes the complete new generation. Another writer can publish afterward, showing that the OS released the writer lock. These are real process terminations, not cancellation mocks.

The Windows ACL qualification applies explicit deny-write/delete rules to every snapshot directory and file, proves create/append/delete fail with `UnauthorizedAccessException`, proves a real publication fails with `snapshot_io_failed`, then runs real CLI status, symbol and reference queries successfully. File/directory inventory and all bytes remain unchanged; original ACLs are restored and temporary fixtures removed.

The first concurrency run exposed Windows `File.Move(overwrite: true)` failing while a reader held the pointer open. Replacing the existing pointer with `File.Replace` fixed both the timing-based reader race and a deterministic test holding the old pointer open throughout commit. The first input integration run also exposed missing import events in Roslyn's binlog; explicit evaluation replaced that unproven collection route and its context limitation remains visible.

Real workspace tests cover an external imported target, nondefault assets path, external binary replacement with equal size/timestamp, SDK inventory changes, environment changes without raw-value disclosure, source additions, absent ancestor candidates and multi-target/generator partial coverage. Malformed nested manifests fail explicitly.

Environment qualification discovered that this automation host injects a different `CODEX_TOOL_CALL_ID` into each tool invocation. The all-environment fingerprint correctly invalidates it; the product does not silently exclude it, because arbitrary MSBuild inputs can reference environment properties. Qualification launches remove that host-only variable explicitly from **both** indexing and query child environments (`$env:CODEX_TOOL_CALL_ID = $null` in each PowerShell launch). This defines a consistent build context; it is not a bypass of freshness checks. Other callers must likewise retain the same explicit environment between indexing and querying. No raw environment values are retained in evidence.

After incrementing to **0.00.12**, the complete Debug validation passed **118 .NET tests and 21 Python tests**, with matching CLI version. Regenerated CodeAtlas and small fixture manifests passed separate-process status/type queries in the controlled environment: verified generation, `isStale: false`, no verification diagnostics, and explicit partial input coverage. ## Reproduction

Run query qualification only after indexing, builds and tests have finished. Set the same controlled environment in every separate launch. Qualification uses one excluded warmup and five fresh query processes per case; it compares complete returned records, order and total counts with the retained index.

```powershell
$env:CODEX_TOOL_CALL_ID = $null
$smallManifest = (Get-ChildItem tests/Fixtures/.codeatlas/solutions/*/current.json).FullName
python scripts/benchmark-query.py --cli src/CodeAtlas.Cli/bin/Debug/net10.0/codeatlas.dll `
  --index $smallManifest --label milestone4-small-v12 --scope small --mode qualification --profile `
  --conditions "No concurrent builds tests or indexing; consistent controlled child environment"
```

For the large run, supply the final index command's stable `index` manifest path, label `milestone4-large-v12` and `--scope large`. Do not pass the immutable JSON artifact as the qualification input: ordinary reads must exercise manifest resolution and integrity verification. Retained reports under `.codeatlas/query-benchmarks/` include all warmups, measured outputs, executable hashes, phase times, process memory and absolute budget assessments. The complete comparison command is `python scripts/compare-indexes.py <earlier-generation-index.json> <final-retained-index.json> --output <new-evidence-directory>`; its inputs are actual index artifacts, not manifests.

## Repair validation and retained generations

Full current-schema loads require both documentation and structural catalogs. Publication writes a sibling `generation.json` manifest mirror before committing `current.json`; an immutable `snapshotIndex` resolves its own verified catalog even after the active pointer moves. A complete copied generation can be inspected in another directory without attaching the new active generation. Existing split generations remain verifiable through their original manifest. A raw old split `index.json` without its manifest requires explicit unverified inspection; never imply it is a complete verified snapshot.

`compare-indexes.py` accepts verified manifests and complete immutable generations, checks every artifact hash/identity, and retains ordered semantic token/provenance sequences. `--allow-unverified-raw` is an explicit diagnostic compatibility option. Mixed-schema comparisons report their common supported scope rather than claim full newer-catalog equality. `benchmark-index.py --retain-index` now retains the whole generation and its mirror, not only an unusable split index file. See [repair evidence](REPAIR-VALIDATION.md) for current checks and pending release gates.
